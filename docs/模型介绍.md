# 模型介绍：双引擎检测模型（病虫 PP-YOLOE+_S + 杂草 PP-PicoDet-L）

> 本分享包覆盖同一演示系统（"慧眼识农"）的**双引擎**：
> - **病虫引擎**：PP-YOLOE+_CRN_S-640，14 类农作物病虫害检测（5 类害虫 + 8 类病害 + 1 类健康状态），7.93M 参数（第一~五节）
> - **杂草引擎**：PP-PicoDet-L-640，12 类棉田杂草检测，5.80M 参数（第六节）
>
> 两者均为飞桨 PaddleDetection 实现，训练目标同款（VarifocalLoss + DFL + GIoU + TaskAlignedAssigner，公式与两引擎参数对照见《模型核心公式手册.docx》）。
> 编写日期：2026-10-08，2026-10-10 增补杂草引擎（所有数字均经独立复算/评测脚本复核，评测脚本与原始日志随本文件夹提供）

## 一、模型概述

PP-YOLOE 是百度飞桨团队提出的单阶段 anchor-free 目标检测模型（PP-YOLOE: Further Evolving the Anchor-Free YOLO Detector，2022）。我们选用的 **PP-YOLOE+_S（Small）** 是其轻量档，在 COCO 上达到 43.9 mAP，官方定位即为"高精度、低延迟的产业级部署模型"。

在本项目 14 类病虫害数据集上，用 COCO 预训练权重微调 100 epoch 后：

| 口径 | mAP@[.5:.95] | mAP@0.50 |
|---|---|---|
| val（1324 图，训练链路 Best） | 0.421 | 0.639 |
| **val（1324 图，导出部署链路）** | **0.427** | **0.648** |
| **test（658 图，导出部署链路）** | **0.419** | **0.648** |

部署口径与训练口径一致、val 与 test 一致——无导出损失、无过拟合。CPU 推理 **0.21 秒/图**（Intel 13 代笔记本 CPU 4 线程，含预处理与后处理，1324 图全量实测 284 秒）。

## 二、与原方案（PicoDet-L）的架构对比

### 2.1 架构设计差异

两者同为飞桨生态的轻量级 anchor-free 单阶段检测器，**训练目标几乎相同**（分类都用 VarifocalLoss，回归都用 DFL + GIoU，标签分配都用 TaskAlignedAssigner，且我们微调时超参数对齐），**真正的差异在骨干网络与特征融合的容量设计**：

> 注意区分两个"PicoDet-L"：本节的 PicoDet-L 是**病虫数据上的前代基线**（已退役，仅作对照）；**杂草引擎**是同架构模型在棉田杂草数据上的独立应用（现役交付，见第六节）。

| 维度 | PicoDet-L（原方案） | PP-YOLOE+_S（最终方案） |
|---|---|---|
| Backbone | **PPLCNet**（scale 2.0）：MobileNet 风格深度可分离卷积，为 CPU 极致轻量设计 | **CSPResNet-s**（depth 0.33 / width 0.50）：CSP 多分支结构 + 大 stem，表征能力显著更强 |
| Neck | LCPAN（轻量 PAN 变体） | **CustomCSPPAN**（CSP 块 + SPP，stage 1 / block 3，输出 768/384/192 通道） |
| 检测头 | PicoHeadV2（轻量分离式头） | PPYOLOEHead（任务对齐头，grid cell 表示） |
| 标签分配 | TaskAlignedAssigner (topk 13) | TaskAlignedAssigner (topk 13)——**同款** |
| 分类损失 | VarifocalLoss | VarifocalLoss——**同款** |
| 回归损失 | DFL (0.5) + GIoU (2.5) | DFL (0.5) + GIoU (2.5)——**同款** |
| 激活 | ReLU / HardSwish | Swish |
| 参数量 | 5.80M | **7.93M**（+37%） |
| 输入尺度 | 640（多尺度 576~704 训练） | 640（多尺度 576~704 训练）——**同款** |

一句话概括：**两代方案用同样的训练目标，差别只在"特征提取器与特征融合的容量"**。PicoDet-L 把参数预算压到极限（5.8M），代价是特征表征能力；PP-YOLOE-S 用 +37% 的参数换来明显更强的骨干网络。

### 2.2 精度对比（同数据、同尺度、同超参的受控实验）

两个模型在**完全相同的数据（train_r2_balanced，含 15% 空图负样本）、相同的 640 多尺度训练配方**下训练，构成严格的架构对照：

| 口径 | PicoDet-L | PP-YOLOE+_S | 差值 |
|---|---|---|---|
| val 训练链路（Best） | 0.3694 / 0.6044 | **0.421 / 0.639** | **+5.2 / +3.5 点** |
| val 导出部署链路 | 0.3774 / 0.6164 | **0.427 / 0.648** | +5.0 / +3.2 点 |
| test（658 图） | 0.363 / 0.607 | **0.419 / 0.648** | +5.6 / +4.1 点 |

关键背景：我们的评测噪声区间经 bootstrap 置信区间测定为 **±0.04 mAP**。PicoDet 时代所有训练策略优化（数据再平衡、续训、小 batch 精调）的增益都在噪声内（0.361 → 0.369 → 0.359）；**换用 PP-YOLOE-S 的 +5.2 点是全项目唯一远超噪声的模型侧变更**，且在 test 集上复现（+5.6）。

### 2.3 消融实验：为什么不是更大的模型？

| 模型 | 参数量 | val（训练链路） | 结论 |
|---|---|---|---|
| PP-YOLOE+_S | 7.93M | **0.421 / 0.639** | 主模型 |
| PP-YOLOE+_M | 23.5M（容量约 3 倍）¹ | 0.426 / 0.642 | 持平（噪声内）→ **瓶颈在数据不在容量** |
| （对照）PicoDet-L | 5.80M | 0.3694 / 0.6044 | 前代基线 |

M 档 300 epoch 完整训练后与 S 持平——说明在当前数据规模（约 1.1 万训练图）下，**7.93M 参数已经吃满了数据所能支撑的精度上限**，继续堆容量无收益。8M 附近就是本任务"精度-成本"的最优工作点。

### 2.5 可靠性与误报特性（部署视角）

| 指标 | 数值 | 说明 |
|---|---|---|
| ECE（10 分箱，N=235,889 候选框） | **0.0546** | 置信度校准良好，分数可直接当作可靠度使用 |
| 逐框精确率 @0.80 | 全量 0.958 / 害虫 0.994 / 病害 0.803 | 高置信检出几乎不出错（recall 0.33，softmax 头分数保守） |
| 逐框精确率 @0.35 | 0.678 / 0.852 / 0.398（recall 0.832） | 演示系统默认阈值 |
| 健康叶图误报 | **0.5 个/图**（13 张实测） | 前代 PicoDet 为 1.8 个/图，大幅改善 |
| 非目标类图误报 | 0.35 档 1.73 个/图（21 张/20 类） | 逐框匹配：63% 为跨类命中（框对类错）、37% 纯虚警——失效模式以前者为主 |

### 2.6 融合优化证伪（单模型即充分）

对主模型尝试的三种免训练融合**全部无增益**：

| 实验（val 导出链路） | mAP | mAP50 |
|---|---|---|
| 单模型 640（基准） | **0.427** | 0.648 |
| TTA（640+960 双尺度） | 0.422 | 0.650 |
| ensemble（+PicoDet） | 0.403 | 0.651 |
| 三路融合 | 0.408 | 0.655 |

有趣的方法论发现：PicoDet 时代 TTA 曾带来 +2.1 点显著增益；主模型足够强之后，弱分支反而拖累融合。**单模型 640 就是最终交付形态。**

## 三、选择理由（总结）

1. **精度显著且可复现**：受控对照 +5.2 mAP（远超 ±0.04 噪声），test 集复现 +5.6，是全项目唯一"确定性提升"；
2. **容量-成本最优**：M 档容量约 3 倍（23.5M）仍零增益，证明 S 档是当前数据下的最优工作点，继续堆参数不划算；
3. **部署友好且已全链验证**：CPU 0.21s/图满足实时演示；导出无损（0.421→0.427）；已打通 Paddle-Lite 安卓端部署（模型转换的三个算子兼容问题均已解决，模拟器端到端实测通过）；
4. **校准可靠**：ECE 0.055，置信度可直接用于业务阈值（≥0.80 高置信检出精确率 0.958）；
5. **误报改善**：健康叶误报从 1.8/图降至 0.5/图，安全失败模式更适合农业场景。

## 四、训练配置摘要

（完整配置见 `01_训练配置/ppyoloe_plus_crn_s_100e_agripest.yml`）

- 框架：PaddleDetection 2.9.0 + PaddlePaddle 2.6.2（单卡 RTX 3090）
- 预训练：COCO 80e 全量检测权重（backbone/neck 正常加载，head 分类层因类别数不同自动跳过）
- epoch 100 / batch 12 / base_lr 2e-4（官方 0.001@bs64 线性缩放）/ Momentum 0.9 + L2 5e-4
- 学习率日程：CosineDecay(100) + LinearWarmup(2 epochs)
- EMA 开启（decay 0.9998，proj_conv 黑名单）
- 多尺度训练：576~704（与基线配方一致，控制变量）
- 数据：train_r2_balanced.json（约 1.1 万图，弱类过采样 + PlantVillage 9 弱类补充）+ 15% 空图负样本（allow_empty: true, empty_ratio: 0.15，抑制无目标场景误报）
- 最优checkpoint：约 epoch 40（其后过拟合回落，Best 权重即 `02_训练结果/best_model.pdparams`）

## 六、杂草引擎：PP-PicoDet-L-640（棉田杂草检测）

### 6.1 定位与架构

杂草引擎与病虫前代基线**同架构**（PPLCNet ×2.0 骨干 + LCPAN 特征融合 + PicoHeadV2 头，5.80M 参数），部署于演示系统的"杂草"与"综合（双引擎）"模式。与 PP-YOLOE+_S 的架构差异见第二节。两处值得注意的细节：PicoDet 的 **reg_max = 7**（回归分布 8 个离散位置，PP-YOLOE 为 16 → 17 个）；PicoDet 推理时以任务对齐度量 **t = s^α·u^β** 融合分类与定位作为输出分数（use_align_head），与训练期的标签分配度量同式。

### 6.2 数据集（CottonWeedDet12）

- 12 类棉田杂草（按 label_list 顺序）：长芒苋 / 牵牛花属 / 马齿苋 / 斑地锦 / 粟米草 / 豚草 / 鳢肠 / 刺黄花稔 / 长序苋 / 镰荚决明 / 牛筋草 / 裂叶酸浆
- 来源：Zenodo 7535814（密西西比州立大学试验农场 2021 年 6-9 月采集，CC BY-NC 4.0，非商业使用需注明出处）
- 规模：5,648 图 / 9,370 框，每图至少 1 框（无背景图）；类别头尾比 **16.9:1**（长芒苋 1959 vs 裂叶酸浆 116）
- 划分（双口径）：随机划分（种子 0）3,670 / 1,130 / 848 与分层划分 3,661 / 1,134 / 853；训练集弱类过采样 16.9:1 → 5.3:1（5,613 图）

### 6.3 训练配置

（完整配置见 `01_训练配置/picodet_l_640_agriweed.yml`，自包含可直接训练）

- 服务器 RTX 3090 单卡：epoch 200（早停）/ batch 12 / base_lr 0.015（官方 0.06@bs48 线性缩放）/ CosineDecay(200) + LinearWarmup(500 steps) / Momentum 0.9 + L2 4e-5
- 标签分配：前 100 epoch 以 ATSS（topk 9）静态分配热身，之后 TaskAlignedAssigner（topk 13、α 1.0、β 6.0——与病虫引擎同参）
- 多尺度 576~704；640 预缩缓存（原图直训解码瓶颈 GPU 利用率 9%，缓存后 21 img/s）
- **Best val mAP50 = 0.845 @ epoch 110**（早停收束），权重即 `02_训练结果/best_model_picodet_l_agriweed.pdparams`

### 6.4 成绩（双口径 test，阈值 0.35，导出部署链路）

| 口径 | mAP50 | mAP@[.5:.95] | 说明 |
|---|---|---|---|
| **随机划分（种子 0）** | **0.9646** | **0.9003** | 12 类全部 ≥ 0.915；最稀有类粟米草 0.915，镰荚决明 / 裂叶酸浆 1.000 |
| 分层划分 | 0.9156 | 0.8382 | 最差类 0.856（尾部类 val/test 样本极少所致） |
| CWFID 域外（甜菜田 60 图） | — | — | 3.12 检出/图、零检出 1/60（域外泛化观察） |

逐类明细见 `03_评测/杂草_终评_随机划分.md` 与 `杂草_终评_分层划分.md`。

### 6.5 INT8 量化探索：不采用，FP32 部署

对杂草引擎尝试了 PTQ 全图静态量化（PaddleSlim quant_post_static，hist 校准 + 逐通道权重量化 + 偏置校正，两轮不同校准集）：

- 体积 22.54MB → 6.76MB（约 1/3.3）
- 但**精度灾难性崩坏**：mAP50 0.9646 → 0.209 / 0.266（两轮一致）；检出框系统性膨胀为近全图大框（中位 369×541 px）+ 类别大面积混淆（域外 59/59 全判同一类）
- 且量化图为 fake-quant 形态，Paddle CPU 运行时反而慢 15~17×（766ms vs 52ms/图）

结论：**杂草引擎以 FP32 部署**。INT8 仅在病虫引擎上以 QAT（量化感知训练，PACT）方式验证可行——体积 -74%、mAP 仅 -1.1 点，与杂草 PTQ 的崩坏形成对照，也说明轻量头的解码路径对纯训练后量化更敏感。完整证据链见 `03_评测/杂草_INT8探索报告_不采用.md`；病虫 QAT 配置与 INT8 模型随包提供（`01_训练配置/ppyoloe_plus_crn_s_qat_agripest.yml`、`04_部署模型/ppyoloe_s_640_int8_qat/`）。
